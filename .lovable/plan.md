# KeyP 단순 채팅형 알림 UX

## 목표
사용자가 자연어 한 문장을 등록하면 최초 참고 결과 1개를 받고, 이후에는 등록 시점 뒤에 생긴 검증된 새 정보만 대화와 알림으로 받는 흐름으로 단순화합니다. 기존 OpenAI·Grok·Daytona·소스 라우팅·근거 판정·기회 탐색 기능은 유지합니다.

## 구현 범위

### 1. 기준선과 중복 방지
- `context_watches`에 `baseline_at`, `findings`에 `is_baseline`, `published_at`, `canonical_url`, `content_hash`, `semantic_fingerprint`를 추가합니다.
- URL 정규화, 소스 ID 추출, 정규화 본문 해시를 조합해 중복 키를 만들고 동일 내용의 재게시도 차단합니다.
- 최초 실행은 가장 높은 매칭·최신 결과 1개만 baseline으로 저장하며 알림 큐에는 넣지 않습니다.
- 이후 실행은 `published_at >= baseline_at`인 결과만 새 알림 후보로 인정합니다. 게시일이 없으면 최초 관측이며 기존 스냅샷·해시에 없는 경우만 인정합니다.
- 기존 결과는 `last_seen_at`만 갱신하고 알림을 만들지 않습니다. 실질적 내용 변경은 새 fingerprint일 때만 update 후보로 처리합니다.

### 2. API와 알림 상태
- watch 생성 API가 의도 해석, 저장, 최초 검색까지 한 번에 수행하고 baseline 결과 또는 정직한 빈 상태를 반환하도록 변경합니다.
- 일반 응답에서는 내부 로그와 엔진 디버그 정보를 제거합니다.
- scheduler 실행은 새 finding만 저장·반환하고 threshold 이상이면 `notification_queue`에 queued 상태로 생성합니다.
- 알림 목록·읽음 처리와 watch 일시정지·삭제·주기 변경을 위한 최소 API를 추가합니다.

### 3. 단순 채팅 화면
- 메인은 로고, 채팅, 벨, 설정만 남기고 엔진 상태·파이프라인·아키텍처·대시보드 지표를 제거합니다.
- 첫 화면은 “무엇을 찾아드릴까요?” 입력과 “알림 받기” 버튼만 중심에 둡니다.
- 등록 후 사용자 문장, KeyP 응답, `최근 참고 정보` 카드 1개 또는 정직한 빈 결과, “계속 찾는 중” 상태를 대화처럼 표시합니다.
- 이후 새 finding은 날짜 구분선과 `새로 찾았어요`/NEW 표시로 history에 추가합니다.
- 결과 카드는 출처·상대시간·제목·요약·매칭률·접힌 이유·원문 링크만 기본 표시합니다.

### 4. 탐색과 설정
- 데스크탑은 얇은 watch 목록, 모바일은 햄버거 드로어를 사용합니다.
- watch 메뉴에서 일시정지·삭제를 제공하고 검색 주기는 상세 설정에서만 노출합니다.
- 기존 Opportunity/Agent 기능은 삭제하지 않고 `/opportunities` 보조 화면으로 이동합니다.
- `/docs`에는 기존 기술 설명을 유지합니다.

### 5. 웹 알림 기반
- 벨에 unread badge와 알림 패널을 연결하고, 새 알림 감지 시 toast를 표시합니다.
- 권한이 이미 허용된 경우 브라우저 Notification도 표시합니다.
- service worker를 추가해 notification click이 watch/finding 위치로 이동하도록 준비합니다.
- 외부 push/VAPID가 없으면 백그라운드 원격 push 성공을 가장하지 않고 코드와 TODO만 둡니다.

### 6. 디자인 시스템과 검증
- `DESIGN_SYSTEM.md`에 색상, 글꼴, 간격, radius, 채팅 bubble, finding card, sidebar, 알림, 반응형, 접근성, do/don’t를 기록합니다.
- 거의 흰 배경, 760px 대화 폭, 1px 중립 테두리, 16px radius, 최소 그림자, 제한된 indigo를 적용합니다.
- 실제 브라우저에서 390px·1280px 화면, 등록→최초 결과/빈 상태, 기술 UI 비노출, 동일 결과 재수집 중복 방지, baseline 이전 결과 재알림 방지, 신규 fixture 알림·unread·대화 추가를 검증합니다.
- 타입 검사와 자동 빌드 상태를 확인합니다.

## 기술 세부사항
- 새 스키마는 기존 테이블과 스케줄러 잠금 함수를 확장하며 RLS와 service-role 권한을 유지합니다.
- 게시일은 수집 근거에서 명시적으로 확인된 값만 사용하고 추정하지 않습니다.
- 알림 polling은 열린 앱에서 가볍게 동작하며, 원격 background push는 VAPID/provider 연결 전까지 비활성입니다.
- 테스트 fixture는 프로덕션 결과를 오염시키지 않는 테스트 전용 경로 또는 단위 테스트에서만 사용합니다.
